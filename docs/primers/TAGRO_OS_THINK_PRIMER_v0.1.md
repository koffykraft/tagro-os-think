# TAGRO OS Think Primer v0.1

**Status:** WORKING  
**Provenance:** SHARED  
**Purpose:** Foundational rule set for thinking before implementation.

## 1. TAGRO OS is an operating system for reality

TAGRO OS should not begin from software screens. It begins from the real system being operated.

Reality contains people, places, resources, constraints, events, history, uncertainty, competing priorities and change. Software is only one interface into that reality.

## 2. Mothership Principle

A durable host preserves identity and continuity while specialist capabilities dock to it.

For farming, the farm or field is the mothership. Irrigation, soil, weather, labour, machinery, crop, nutrition, finance and other capabilities are docks. No dock should own the entire farm model.

## 3. Planar Principle

A single fact or event may appear on multiple operational planes without becoming multiple facts.

Rainfall can affect weather, soil water, irrigation requirement, labour, energy and crop state. The event is recorded once; each plane interprets it for its purpose.

## 4. Flux Principle

Change is not an exception. Flux is part of system existence.

The system must distinguish sufficiently confirmed information from provisional, estimated, proposed or changing information and propagate consequences when change occurs.

It should ask:

- What changed?
- What does this affect?
- What remains valid?
- What must be recalculated or reconsidered?
- What is physical reality versus current proposal?

## 5. Provenance

Information should retain where it came from and what confidence is justified.

Useful states include:

`OBSERVED · DESCRIBED · MEASURED · INFERRED · CONFIRMED · PROPOSED · ACCEPTED · INSTALLED`

Inference must not silently become fact.

## 6. Capture before prescription

The system should accept information in the form easiest for the human:

- speech
- text
- photograph
- map mark
- rough sketch
- measurement
- selection
- imported record
- sensor or external data

The information process should structure the input behind the scenes rather than require the user to understand the internal data model.

## 7. Ask only consequential questions

A missing detail does not automatically justify a question.

The system should ask for additional information when the answer materially changes a decision, risk, calculation, or recommended next action.

## 8. Preserve history

New evidence can supersede an older estimate without deleting the older evidence.

Git history, event history and object state history should make it possible to understand how current thinking or design was reached.

## 9. Physical reality outranks recalculation

An installed object is not silently replaced because a new calculation prefers something else.

The system should recognize installed reality, expose consequences, and redesign around it or explicitly propose modification.

## 10. Recalculate by dependency

Changes should propagate through real dependency relationships at the smallest useful scope.

A changed emitter can affect lateral demand, submain demand, main demand, pump loading, irrigation duration and BOM. A change in one independent plot should not invalidate unrelated confirmed work.

## 11. Human engineering is part of engineering

A hydraulically correct valve in an inaccessible location is a poor system design.

Access, maintenance, labour, paths, entrances, security, machinery movement, usability and affordability belong in design logic.

## 12. Farming systems, not isolated irrigation

TAGRO Farming Systems should treat irrigation as one dock among many:

`LAND · SOIL · WATER · WEATHER · CROP · PLANT · NUTRITION · IRRIGATION · LABOUR · MACHINERY · POWER · FINANCE · MARKET · HARVEST · PEST/DISEASE · ACCESS · HOUSEHOLD USE · RECORDS`

Irrigation consumes relevant facts from these docks and returns decisions, events and consequences to the wider farm system.

## 13. No final state

The operating loop is:

`REALITY → OBSERVATION → EVIDENCE → KNOWLEDGE → INTERPRETATION → OPTION → DECISION → IMPLEMENTATION → OPERATION → NEW REALITY`

The cycle continues.

## 14. Governing proposition

> Preserve what is known. Keep what may change revisable. Propagate consequences, not assumptions. Never confuse the current answer with permanent truth.

## Version note

This is v0.1: a working primer, not final doctrine. Later versions should preserve traceability to this version and explicitly record changes in meaning.
